# Torrentino — план проекта

> Небольшой, быстрый и настраиваемый BitTorrent-клиент для macOS.
> Сценарий использования: кидаешь `.torrent` файл (или magnet) в папку — он сам подхватывается и быстро скачивается.
> Цель — избавиться от глюков/зависаний, которые встречаются в qBittorrent и подобных клиентах.

---

## 1. Проблема

Существующие клиенты (qBittorrent и др.) со временем начинают:
- подвисать и «замерзать» (UI и/или движок);
- терять скорость / плохо работать с очередями;
- неудобно настраивать под агрессивное скачивание (много потоков, лимиты).

Хочется **маленькую, стабильную, быструю** программу с:
- максимальным числом соединений/потоков (настраиваемо);
- простым «закидыванием» torrent-файлов;
- возможностью менять параметры на лету.

## 2. Исследование: какие движки существуют (GitHub)

| Проект | Язык | Лицензия | Звёзды | Зрелость | Комментарий |
|---|---|---|---|---|---|
| **arvidn/libtorrent** (libtorrent-rasterbar) | C++ | BSD-3 | ~6.0k | 15k+ коммитов | Самый зрелый и быстрый движок. На нём qBittorrent, Deluge. Огромная конфигурируемость (очереди, кэш, соединения). Минус: тяжёлая C++ сборка, сложно оборачивать. |
| **anacrolix/torrent** | Go | MPL-2.0 | ~6.1k | 4.2k коммитов | Полноценная библиотека + CLI (`torrent download`). DHT, PEX, MSE-шифрование, magnet, стриминг, webseed. Чистый Go, легко встраивать. Минус: Go не установлен (ставится через brew). |
| **transmission / libtransmission** | C/C++ | GPL-2/3 | ~15k | 16.8k коммитов | Легендарно лёгкий и стабильный. Есть headless-daemon + Web UI. Минус: большой монолитный проект, GPL. |
| **ikatson/rqbit** | **Rust** | Apache-2.0 | ~1.8k | 2k коммитов | Клиент + **библиотека `librqbit`** + HTTP API + Web UI + Tauri desktop. DHT, PEX, uTP, magnet, стриминг, UPnP. Активно развивается. |

### Вывод
Для нашей задачи оптимальна база **rqbit / librqbit (Rust)**, потому что:
1. **Rust уже установлен** в системе (1.97.1) — не нужно ставить новый тулчейн.
2. Это **готовый современный движок** со всеми нужными фичами (DHT/PEX/uTP/magnet/шифрование).
3. Есть **библиотечный API** (`librqbit`) — можно встроить как ядро и сверху сделать свой интерфейс.
4. Есть готовый **HTTP API + Web UI** — можно переиспользовать для управления.
5. Rust даёт стабильность/отсутствие «утечек» и зависаний, на которые жалуемся в qBittorrent.

**Альтернатива (если захотим):** `anacrolix/torrent` на Go — чуть проще API, но придётся ставить Go.
**Эталон по качеству/скорости:** `libtorrent` (C++) — держим в голове как референс настроек.

## 3. Что умеем из коробки (через rqbit) и что добавим сами

### Даёт rqbit/librqbit:
- BitTorrent protocol, DHT, PEX, uTP, MSE (шифрование), magnet-ссылки, webseed;
- добавление торрентов по файлу/magnet/URL;
- HTTP API (`POST /torrents`, pause/start/delete, статистика, стриминг);
- Web UI;
- UPnP port-forwarding;
- конфигурация через CLI-флаги и env.

### Добавим сами (ценность Torrentino):
1. **Watch-folder** — следим за папкой (напр. `~/Downloads/torrents-inbox`): появился `.torrent`/`.magnet` → автоматически добавляем в закачку, файл переносим в `processed/`.
2. **Конфиг TOML** (`~/.config/torrentino/config.toml`) — все тюнинги в одном месте:
   - папка загрузок, порт, лимиты;
   - `max_concurrent_torrents`, `peer_opts` (лимиты соединений на торрент/глобально);
   - скорости up/down, размеры очередей;
   - включать/выключать DHT/PEX/uTP/шифрование.
3. **CLI + живой прогресс** — красивый вывод статуса (скорость, пиры, прогресс) в терминале.
4. **Горячая перезагрузка конфига** — меняем параметры без перезапуска.
5. *(опционально)* TUI (ratatui) или переиспользование Web UI rqbit.

## 4. Архитектура

```
Torrentino/
├── Cargo.toml
├── PLAN.md
├── README.md
├── config.example.toml
└── src/
    ├── main.rs        # CLI: run / add / status / server
    ├── config.rs      # загрузка/валидация TOML-конфига
    ├── engine.rs      # обёртка над librqbit (Api/Session)
    ├── watcher.rs     # watch-folder (notify crate)
    └── ui.rs          # вывод прогресса в терминал
```

Зависимости (предварительно):
- `librqbit` — торрент-движок;
- `tokio` — async runtime;
- `serde` + `toml` — конфиг;
- `notify` — слежение за папкой;
- `clap` — CLI;
- `anyhow` — ошибки;
- `indicatif`/`comfy-table` — красивый вывод (опц.).

## 6. Риски / открытые вопросы

- **API librqbit** может быть не самым стабильным (проект активно меняется) — фиксируем версию в Cargo.toml.
- **Сборка** может тянуть много зависимостей (tokio, openssl и т.п.) — проверим на этапе 1.
- Если librqbit покажется неудобным — **план Б**: Go + anacrolix/torrent (поставить Go через brew).
- Нужен тестовый торрент для проверки (легальный образ Ubuntu/Debian).
